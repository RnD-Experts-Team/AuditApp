One request for the whole follow-up grid. GET /plans?week_start= returns every visible store's week — plans, judgement and the previous weeks' boundaries. Without it this screen would call /stores/{id}/week once per store: 44 requests, each triggering its own token check against pizzasys.

The judgement is 40% of the score and the only thing the specialist writes. No system holds it — the data project doesn't know whether the stickers were applied, the inventory system doesn't know whether the dough was any good. "Judged" means both verdicts are in; a half-filled row still counts as pending.
